## 目标
把 FTC 系内转移段速度模型从「只由 f 决定」改成正确结构，并用实测标定到可用。

## 边界
- 不做：不改走「每次问服务器」的路子（保留本地模型）
- 不做：不用 <5 点的样本宣称常数已标定
- 不做：不动 STL_INTRA_TRANSIT_SPEED_KM_S 锚点，除非第 4 步数据明确支持
- 必须：每条断言改动先经变异验证（证明能真的报错）
- 必须：compile + lint 全绿才算完
- 必须：扫描产物能自证当次部件配置（引擎/质量/罐）

## 已定参数
- 对照粒度：**逐罐 + 端点对照**（每罐对 f=0.05 与 f=0.5）
- 第 3 步只扫罐×f，**payload 固定 0**（载重是下一条主轴）
- 第 5 步拟合目标：三档罐 18+ 点逐点误差 ≤15%

## 7 步

### 1. 让转移段扫描产物记录蓝图快照（引擎/整备质量/罐容量）
- 验收：新导出 JSON 每变体带 engine / operatingEmptyMass / stlFuelCapacity，与游戏蓝图面板逐个核对一致
- 前置：无
- 坑：① 引擎选项在 blueprint.selections，不在 performance，取法先确认字段名；② 改完必须重开 BTF/蓝图窗口（缓存旧配置）；③ scanTransitMatrix 与 scanTransitFuelCurve 两条路径都要带，别只改一处

### 2. 建立「逐罐+端点」面板对照流程，并对当前罐跑通一次
- 验收：同罐同航线，原生 BTF 面板与 FTC 扫描器在 f=0.05 与 f=0.5 两个端点，四项指标（距离/耗时/燃料/速度）差异 ≤1%（轨道漂移单独记录、不计失败）；产出对照记录文件（含时间戳）
- 前置：第 1 步
- 坑：① 面板必须用游戏自带 autocomplete 选起终点，直接填值会显示 ••• 但未提交；② 比对前先打印被测对象的 tank/blueprint/f 标识再比数值（上次没打印标识读错行，得出假结论）；③ 滑块拖动后要确认表格已重算

### 3. 重采 (罐×f) 网格：含第二种引擎，每罐带端点对照
- 验收：≥2 种引擎、每种 ≥3 档罐（1500/3500/8000）；每罐 f=0.05 与 f=0.5 有面板对照记录；每点 transitFuel≈0.98×罐×min(f,0.5)（±5%）
- 前置：第 1、2 步
- 坑：① 同蓝图换罐后必须点「保存」，否则服务器按旧配置算；② Chrome 对同名下载自动改名，归档前必须打开文件核对 stlFuel 字段；③ 换引擎需新建/修改蓝图，注意 BTF 缓存

### 4. 写离线拟合脚本：判定模型形式并报可辨识性
- 验收：读网格 JSON，对候选形式打印逐点误差表，明确输出参数可辨识性判断；自由参数数 ≥ 数据点数时报「不可辨识」；带退出码（达标 0 / 不达标或不可辨识 1）
- 前置：第 3 步数据
- 坑：① 3 点 3 参数必然不可辨识，脚本要能识别而非硬给一组数；② 只做分析，不写进 src/（写源码是第 5 步）

### 5. 改 fuel-model.ts 的系内转移段速度式
- 验收：新式在网格上逐点误差 ≤15%；旧式在同一数据上误差 ≥50%（证明改动有意义）；先跑全量回归记录「改前哪些脚本依赖旧口径」
- 前置：第 4 步
- 坑：下游 4 个消费者（最优方案行/邻档对比表/FLEET 链式飞行时间/SFC 联动写滑块）都消费该速度，改了会动时间梯度，先看清炸点再改

### 6. 更新受影响的回归断言与 feature-patterns 文档
- 验收：全部 verify-*.mjs 绿；docs/feature-patterns.md 的转移段速度/f 曲线口径与代码一致；每条被改断言写明「断言变更记录（日期+原因）」
- 边界：不许为了让测试变绿而改断言迁就错误模型 —— 断言失败是模型错就先修模型
- 前置：第 5 步

### 7. 全量回归 + compile + lint 收尾
- 验收：pnpm run compile 与 lint 全绿；全部 verify-*.mjs 绿；产出「新模型 vs 旧模型 vs 网格实测」逐点误差对照表
- 前置：第 6 步，上一步遗留失败清零
- 坑：compile 用 vue-tsc（查 .vue），lint 是 eslint，两条都要跑
