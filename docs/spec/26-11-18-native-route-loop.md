# 原生 RT 循环执行（XIT FLEET）

> 状态：已实现（待浏览器验收）。纯数据/计算层（步骤 1–3、4 核心、6 数据、8 文档）、向导/规划 UI（步骤 4b、5）与运行中卡片循环状态/补货/预检（步骤 7）均已落地。UI 均需浏览器验收；RTE 阻塞/等待中文文案、缺量时步骤等待最少数量的实机表现待验收。

给 XIT FLEET 生成的原生 RT 增加可选「循环执行」：写完航点与装卸步骤后打开游戏自带的 Loop，由游戏服务端反复执行同一闭环。关掉页面后循环仍继续运行。

## 目标

- 单船、单航线：出发地 → 各基地（先卸后装）→ 出发地，Loop 打开后自动进入下一轮。
- 循环模式按**一轮**重算运量，按轮数备货，并在 FLEET「运行中」展示循环状态与阻塞。
- 默认关闭；单趟路径行为不变。

## 非目标

- 不自动在 CX 买卖、不自动维修、不自动处理船况。
- 不做后台轮询；所有服务端请求仍由点击触发（`../contributing.md` 的 ToS 规则）。
- v1 不支持多船分配到同一条循环航线，也不支持多船各自生成循环 RT。
- v1 不支持用 Wait 步骤拉长周期；周期等于飞行周期。

## 现状与约束

- 生成器已写出闭环航点与全部装卸/补油步骤（`../../src/features/XIT/FLEET/native-route-plan.ts` 的 `buildNativeWaypoints`）。
- 单趟与循环均由原生 RT 执行。向导写完单趟航线后保持 Loop 关闭。
- 游戏规则（[官方航线手册](https://handbook.apex.prosperousuniverse.com/wiki/routes/)）：
  - 循环航线在末站步骤完成后从首站重来；Loop 开关在下一轮结束生效。
  - 装卸步骤按最小/最大量移动；不足最小值或目标仓库无空间时原地等待，没有超时。
  - 飞行段阻塞不会自动重试，只能解除分配后重新分配。
  - 循环在 PRO 失效或不同目的地少于 2 个时停止。
  - 同一条航线可被多艘船同时执行；船沿用开始执行时的航线版本，编辑在下一轮生效。
- 航线只能装卸/补油，不能买卖。
- 基地缺料只能等生产；出发地 CX 采购与产物出售必须另行处理。

## 设计

### 模式与资格

- 向导增加「循环执行」复选框，默认关闭。
- 循环模式要求：恰好 1 艘船、至少 1 个基地、至少 2 个不同目的地。
- 循环预览与新建原生 RT 共用一个仓库航点，顺序为 `仓库 → 基地… ↺`。仓库先卸货，再补油、装船，航点档位对应末基地飞回仓库的航段。Loop 关闭生效时航线停在末个基地。单趟 RT 仍单独写入末尾仓库航点。
- 写入顺序：在 FLEET「规划中」查看预览并点「生成原生 RT」→ 检查航点地址与装卸物料 → 建航线 → 添加航点和步骤，按回包补写不符的设置 → 打开 Loop → 读回确认。Loop 打开失败时保留航线，提示手动开启后再分配飞船。
- 重算同一艘船、同一产业链的配货后，可在「规划中」点「预览更新配货」。候选为 FLEET 创建且预览时确认未分配的循环 RT。航点地址、步骤顺序、装卸料号、补油和飞行档位与本轮规划一致时，预览数量差异并沿用原 RT 写入。确认时重新读回航线并核对差异，每条写入后核对回包。中途失败后可重新预览剩余差异。全部数量确认后更新飞行周期、每段估时、油耗和周转货快照。数量已经一致且快照缺失时，也可以只同步本地快照。

### 周期与运量

**周期估算（生成时快照）**

- `cycleHours = estimateChainFlightTimes({ ship, origin, stops, legPayloads, refuelAtOrigin: true, nativeRoute: true }).totalHours`。`legPayloads` 取计划的 `legLoadWeight(plan, i, legCount)`（逐段离站载重）；首段按出发地补满油罐、后续段按上一段余油递推（与原生 RT 只在出发地补满一致，`../../src/features/XIT/FLEET/chain-flight-time.ts`）。
- 估时启用网关，按每段的起飞时刻及余油选择可行整数档位。向导沿用这份循环计划的装卸步骤、档位、出发地补满设置与逐段油耗，备货按同一份油耗计算。任一段缺输入或余油不足时列出航段和原因，并停用循环 RT 生成。
- 配货天数为 `ceil(预计飞行小时 / 24)`，至少 1 天。先按 1 天配货，再按逐段载重估时。向上取整的结果变动时按新天数配货并重新估时，直到两者匹配。
- 实际飞行时长随出发时刻变化，原生 Loop 每轮接着运行。生成后按写入的固定数量装卸。
- 逐站校验「卸货 − 取货 +（日产 − 日耗）× 配货天数」。每轮必需物资短缺、缺装卸物料尺寸、必需装载超出舱容或缺油时，显示对应基地、物料或航段。
- 循环校验失败时，规划仍显示已计算的循环方案和归航数据。只有通过校验的方案可生成 RT。

**循环运量**

- 循环规划和可用天数直接读取基地 BURN。已开工订单的额外日耗与日产折算用于单趟规划。
- 送达量按 `max(0, ceil(配货天数 × (input + workforce − output)))` 计算。自给材料不安排送达，基地库存保留为缓冲。账单由 `loopBurnBill` 生成。
- 提取量按 `floor(配货天数 × (output − input − workforce))` 计算。实际提取可加回本轮送达的自产自耗量（`loopExtractable`），流量分配时先按全额自用扣除。

- 链上产物提取（基地 LOAD）写成精确绝对量，减产轮库存不足该量时原地等待。必需的链上交付和下一轮的周转货优先占用舱容。可选回运用剩余舱容，并按基地和物料显示每轮留存量。
- 组内产出按 BSN 白名单处理。从出发地送出的组内产物优先由同一航线归航补回，实际回运量算作周转货。产量或返航舱容不足的差额计入每轮外部采购，出发地装船量仍按完整需求。当前出发仓库库存和订单簿供给用于备货预览。
- 「满载可用」表示船总舱容 ÷ Σ各基地净日耗，按重量与体积上限取较小值。规划表用 `ChainPlan.fullLoadUsableDays`，向导与运行中卡片用 `nativeRouteUsableDays`。缺少基地 BURN 或净消耗物料重量、体积时显示 —。

**定量装卸与全舱卸载**

- 基地定量装卸、仓库装载和单趟归航定量卸货使用 `min=max=计划量`，缺量时等待。循环仓库的逐项卸货使用 `min=0, max=计划量`，让首轮没有回运货也能开始装船。货舱已有同料号物料时，也会按该上限卸入仓库。
- 同料号的采购卸货与链上卸货先合并。选船初始货舱确认为空且本站卸完后没有留船货物时，用一条原生 `UNLOAD_ALL`，预览仍显示预计清单。回退原生界面填写时使用逐项卸货清单，沿用各航点的最少数量。
- `min=0` 已实采由 `EDIT_LOAD_STEP` 和 `EDIT_UNLOAD_STEP` 接受并回显。新建步骤默认 `min=1`。

**仓储与慢基地**

- 基地装不下或可装库存不足时，原生 RT 等待库存变化。航线运行间隔可能因此长于预计飞行时长。
- 周期只含飞行，不含装卸停留；界面按「飞行周期」展示，不用它冒充精确到港时刻。

### 备货

**每轮出发地账单**

- `roundBill = cxBill + 每轮 SF/FF 消耗`。`cxBill` = 航点 0 的 LOAD 步骤汇总（`nativeRouteOriginBill`，`../../src/features/XIT/FLEET/native-route-purchase.ts`）。
- 每轮 SF/FF = 整圈消耗：v1 只在出发地补满（REFUEL `CAPACITY`），每轮补油量 = 罐容量 − 归航到港余量 = 逐段消耗之和。由估时取逐段 `stlUsed/ftlUsed` 求和（需给 `ChainFlightLeg` 增加油耗字段）；算不出时回退罐容量上限（偏保守）。
- 基地端不采购，只显示本轮卸货/装载与当前库存的差额。
- 罐容量是「吨 → u」换算：`weightCapacity` 单位是吨，要除以燃料单重（SF 0.06 / FF 0.05 t/u）换回 u 并向下取整（`210 / 0.06 = 3499.999…` 的小数尾巴会顺着备货账一路进 CX 采购包）。把吨直接当 u 会把 3500 u 的罐读成 210 u，逐段余油假判缺——单趟估时与 FTC 判缺同样按 u 吃这个值。
- 「该交易所不可买」必须区分「确认无卖单」与「订单簿没下发」：`cxobStore` 只由 `COMEX_BROKER_DATA` 推送填充，而该推送要先打开过对应 CXOB 窗口。所以循环模式下对话框按账单静默打开隐藏窗口（`CXOB SF.AI1`，`autoClose` + `closeWhen` 读到即关）把数据拉回来；仍读不到按未知处理——燃料照进备货包、不报警；只有订单簿存在且 `sellingOrders` 为空才算不可买（排除并提示手动补给）。

**备货轮数 N**

- 默认 1。按重量和体积分别扣除首轮账单，再用剩余容量除以每个后续轮次的外部补给量，取能备的较小轮数。首轮包括实际缺油和周转货，后续轮次仅包括外部补给及每轮耗油。
- 输入框原样保留键入内容（允许清空），只在 `change` 与计算时钳到 `1..Nmax`。逐键回写会把「清空后输入 5」变成「15 → 钳成上限」，用户输的 5 悄悄变成 Nmax。
- 物料重量/体积没下发（`materialsStore` 缺 ticker）时算不出 `cycleW/cycleV`，`Nmax` 直接取 1：宁可少备一轮，也不按偏小的体积报出偏大的轮数、装不下。
- 采购包只含出发地 CX 可买的物料；SF/FF 若该交易所不可买，只提示缺口、不下单。
- 以「首轮账单 + (N − 1) × 后续轮次账单」扣出发地现有库存。备货包生成外部补给的 `CX Buy`，周转货缺口提示手动准备。

**支撑轮数与运行中补货**

- 航线开跑前，先校验首轮的全量装船和补满油箱所需燃料，再以余量计算后续轮次。已运行航线按每轮外部补给量估算并补货。旧航线没有周转货快照时按航点 0 的完整装船量与每轮油耗估算。
- **燃料只认生成时快照**（`record.fuelPerRound`，`loopSustain`）：游戏 UI 手建的循环航线没有快照，按罐容量估会把整圈当成耗满一罐（支撑轮数偏少、误报「不足 1 轮」），完全不估又会把 SF/FF 从账单里漏掉（支撑轮数偏高）。没有快照时一律不给数字：卡片显示「—」、不报「不足 1 轮」、补货包只含物料。
- 船离港后可以从运行中卡片补下一轮的外部补给。按后续一轮账单扣出发地仓库库存，周转货由归航补回。出发地非交易所或已备齐时置灰。
- 运行中卡片的「CX 消耗」打开 `XIT BURN CX <交易所代码>`。汇总经过该 CX 且正在执行的循环航线上的自有基地，每个基地只计一次。日均输入、产出和劳动力消耗直接合并基地 BURN，库存取该 CX 的玩家仓库。「天数」按日均净耗计算，「需要」按全局 BURN 补给天数计算。CX 报告、向导和比价页共用游戏航线列表，打开时缺少列表才发起一次读取，游戏后续推送的航线变更会更新列表。
- CX BURN 的「ACT」打开 `XIT BURNGEN CX <交易所代码>`，沿用全局 BURN 补给天数及当前生产和劳动力筛选。向导可调整天数和物料来源、预览缺口，再生成目标 CX 的补库包。「比价购买」将当前筛选带入 `XIT CBUY CX <交易所代码>`，比较各交易所盘口，操作包在目标 CX 采购。补库包只含 `CX Buy`，缺口已扣目标仓库库存一次。

### Loop 开关

- `RouteData` 增加 `repeats?: boolean`（服务端响应已带该字段，当前类型未声明）。
- **开关报文已实采**（`prun-client-log.json` / `prun-log.json`，2026-11-19）：`SHIP_ROUTES_SET_REPEAT`，payload `{ routeId, repeats: boolean, actionId }`；响应是单条 `SHIP_ROUTES_ROUTE`（完整航线，`repeats` 已翻转）。与现有变更类请求同口径，套用 `native-route-socket` 的 FIFO 串行 + 按 routeId 匹配单条响应。
- `socketSetRouteRepeats(routeId, repeats)` 写入后直接用响应里的 `repeats` 校验（必要时重新 GET）；失败回退界面路径：打开 RT、点击 LOOP、读回状态。
- Loop 开关与航点/步骤独立：实采时航线只有 3 航点、0 步骤即可切 `repeats:true`。写入顺序仍按「建航线 → 航点/档位/步骤 → 开 Loop → 读回」，但开关不必等步骤写完。
- 关闭循环在下一轮结束生效；删除航线前必须先解除分配。
- 循环开关与补货仍由向导/卡片点击触发。

### 执行与备货

- 原生 RT 负责航行、装卸和补油，采购与补货通过 FLEETACT 的独立 CX 采购包完成。
- 升级时停用可识别的旧 FLEET 到港触发器，避免到港时重复装卸。已保存的操作包保留。

### 监控与异常

**状态来源**

- `RouteExecutionRow` 增加 `status`（从行文本解析 Step blocked / Blocked / Waiting 等，`../../src/features/XIT/FLEET/native-route-rte.ts`）；中/英文文案需从 RTE 实采，读不到保留 `undefined` → 显示「—」。
- `RouteData.repeats` 以服务端为准（见 Loop 开关）。
- **轮次号不可读**：RTE 与 `RouteData` 都不暴露「第几轮」。卡片显示「当前站/总站数」（`routeStopStates`/`routeProgressText`），不伪造轮次计数；页面关闭期间的轮次无法累计。

**校准触发**：面板打开停在「运行中」、点页签、向导写入后各校准一次；不轮询（沿用 `collectNativeRoutes` 现有触发口径）。

**卡片显示**：Loop 徽标、飞行周期（标「预计」）、当前站/总站数、阻塞状态、出发地可支撑轮数。

- 循环模式开着但周期没算出来（没选船/0 个基地/缺载重数据/估时抛错）时，横幅给出具体原因，不留空色条；同时「生成原生 RT」置灰。
- 阻塞/等待告警只挂在循环航线上：关键字是从手册候选词推的，未实采前不外溢到单趟卡片。

**告警（含数据源）**

- 步骤阻塞 / 飞行阻塞：RTE 行 `status`。飞行阻塞提示手动解除分配再重新分配。
- 循环停止：`ship.assignedRoute` 已无该航线但 `repeats` 仍为开。PRO 失效只能由玩家续费后重新分配。
- 船况 <80%：`ship.condition`。
- 出发地库存 <1 轮：支撑轮数 <1。
- 非计划货物占用舱容：`cargoStore` 与计划载重的差额。
- 基地仓储将满：`daysUntilFull` 偏小，或库存 + 本轮配送 > cap。

### 分配前预检

- 恰好 1 艘船、至少 1 个基地、至少 2 个不同目的地。
- 船在出发地，或剩余燃料足够飞到出发地。
- 货舱为空，或剩余舱容足够装下本轮计划；非计划货物必须列出。
- 出发地库存 ≥1 轮（含 SF/FF）。
- 各基地仓储余量够本轮配送（不足则警告，运行中可能阻塞）。
- Loop 已确认打开（`repeats` 读回）。
- 玩家有 PRO（无法可靠读取时只提示）。

## 数据与接口

- `ChainFlightLeg` 增加 `stlUsed?/ftlUsed?`（每段油耗，供每轮 SF/FF 账单）。
- `ChainPlan` 增加 `fullLoadUsableDays?`（满载可用天数，满载加权分摊展示口径：总舱容 ÷ Σ各基地净日耗 bundle）。
- `NativeRouteRecord` 增加 `loop?: boolean`、`cycleHours?: number`。
- `RouteData` / `NativeRouteView` 增加 `repeats?: boolean`，以游戏定义覆盖本地快照。
- `computeChainPlan` 增加稳态 need 口径开关（loop）。`buildNativeWaypoints` 的清舱判断在循环与单趟共用。普通物料装卸按 `min=max=计划量`。
- 新纯函数建议放 `native-route-loop.ts`：每轮装载账单、每轮 SF/FF 消耗、备货轮数上限、可支撑轮数、资格校验。
- 复用 `native-route-purchase.ts` 的缺口算法，输入改为 N 轮账单。

## 实现步骤

1. `native-route-socket.ts` 补 `RouteData.repeats` 与 `socketSetRouteRepeats`（`SHIP_ROUTES_SET_REPEAT`）；装卸步骤写 `minimum=maximum=数量`（报文均已实采）。
2. `ChainFlightLeg` 补逐段油耗；新增 `native-route-loop.ts`（每轮账单、SF/FF 消耗、N 轮备货、资格校验）。
3. `computeChainPlan` 加稳态 need 口径；`buildNativeWaypoints` 定量装卸写 `min=max`，满足清舱条件时写 `UNLOAD_ALL`。
4. `use-chain-loop-planning.ts` 生成按整天配货的循环计划和飞行估算；`ChainView.vue` 展示预览。
5. `NativeRouteDialog.vue` 增加循环选项、写后开 Loop、N 轮备货与警告。
6. `native-route-registry.ts` / `native-route-game.ts` 记录并合并循环状态；`native-route-rte.ts` 解析阻塞状态。
7. `ChainView.vue` 运行中卡片显示循环状态、补货与预检。

## 不采用

- **直接给现有单趟计划打开 Loop**：单趟读取手填天数及当前库存。循环配货按日净耗与日净产计算，还需准备首轮周转货和燃料。
- **按 need（减库存）写循环绝对量**：固定步骤重复执行会逐轮少送、基地饿死；循环按配货天数的净缺口写入。
- **满载送达**：每轮装满可能使基地库存累积或出发地备货不足。满载加权用于显示舱容可承载的补给天数。
- **按基地仓储上限减少配货天数**：各基地按同一天数配货，舱容检查和实际仓储由各自环节处理。
- **Loop + ACT 触发器并存**：原生步骤已经装卸，触发器会重复搬运。
- **多船共用一条循环航线**：每艘船都按同一组绝对量装卸，实际流量按船数倍增，计划失效。

## 验证

回归脚本能覆盖纯模块，覆盖不到的写明归属，不把「有断言」说成「有验证」：

- `../../scripts/verify-fleet-contracts.mjs`：按整天计算的**净缺口**账单（`loopBurnBill`/`computeChainPlan`：日耗扣自产，自给材料不送）、**满载可用天数**（`fullLoadUsableDays`/`netDailyBundle`：舱容 ÷ Σ净日耗 bundle 加权分摊，自给基地不占分摊、缺数据不出数）、24 与 48 小时边界、增加载重后跨档重估、超舱容和无法收敛、备货轮数上限、支撑轮数（`loopSustain` 无每轮燃料快照留空）、循环资格、定量装卸数量和补油容量报文、全舱卸载的单请求写入、同一料号留给后续站时保持定量卸货、`repeats` 合并、`fuelPerRound` 的逐段求和与缺段回退（字面量腿，只测消费端）、**真实 `shipFuelRemainingFor`** 的吨→u 罐容量（0.06 t/u × 210 t → 3500 u，向下取整，余量 100）。
- `../../scripts/verify-chain-flight-time.mjs`：真实公式模型下的**生产端**逐段 SF/FF 实耗（`stlUsed = 出发油量 − 到达余量`，系内为 0 而非回退），并与 `fuelPerRound` 对账。
- 浏览器：单趟和循环均在 FLEET「规划中」预览，飞行列直接显示各段预计 STL/FTL 油耗和档位，含归航段。循环预览沿用写入的档位。多个船只或循环估时不可用时「生成原生 RT」置灰。点生成后先检查地址和物料，失败时在规划中显示问题，通过后在对应飞船的规划卡片内显示当前阶段及已写完的航点数。写入时切换页签和视图，返回「规划中」后仍可看到同一次生成的进度或结果。生成后可定位「运行中」的新航线，并打开采购包或备货包。
- 实机：2 基地 1 船跑满两轮；基地有初始缓冲时多轮不饿死、不溢仓；上游减产轮链上提取/卸载不阻塞；抽掉一种出发地输入验证在出发地阻塞、补货后恢复；航行中补货；关闭 Loop 在下一轮生效。
- 浏览器关闭后循环仍继续；关闭期间不产生扩展请求。
- 打开/点页签才发 `SHIP_ROUTES_GET_ROUTES` / RTE 读取，符合 ToS 例外清单。
