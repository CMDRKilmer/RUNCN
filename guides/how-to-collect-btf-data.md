# BTF 蓝图试航数据采集指南

用 BTF（蓝图试航模拟）面板采集飞船性能/燃料数据的方法（2026-08-29 实测总结）。

## 打开 BTF

- BTF 通过蓝图列表（BLU 页）行的「测试」按钮打开，或点磁贴组内的 `BTF <蓝图>` 标签。
- **蓝图修改后必须关闭 BTF 再重开**：BTF 缓存旧蓝图配置，改引擎/货舱/油箱后不重开算的仍是旧参数。
- BTF 可能以浮动窗口或右侧大磁贴两种形态出现；用 `.Tile__tile` 或 `[class*="Window__window"]` 定位时先确认形态。
- 游戏有「缓存窗口」机制，重复开的 BTF 会进缓存；注意区分并关闭多余的。

## 设置航线

- 出发地/目的地用 `input[type="search"]` 输入，等下拉建议出现后点「搜索结果」首项
  （勿点 Warehouses / Commodity exchanges 等重复项）。
- 输入建议可用坐标点击（`.AddressSelector__suggestion`），locator 直接 click 有时被遮挡超时。

## 设置滑块（燃料消耗 / 反应堆 / 载重 / 低光速燃料 / 超光速燃料 / 船只状况）

- **必须先点击滑块手柄聚焦，再点击轨道目标位置**：直接点轨道不生效（手柄不动、表格不变）。
  ```
  page.mouse.click(handleCenter, trackY + 2);   // 聚焦手柄
  page.mouse.click(trackX + trackW*frac, trackY + 2);  // 点轨道设值
  ```
- 端点值（MIN/MAX）用键盘：聚焦手柄后按 `Home`（最小）/ `End`（最大）。
- **滑轨最右端点点击常失败**（落到最大档之前一档）——最大档务必用 End 键，且读回手柄位置确认。
- 坐标每次重新 `getBoundingClientRect`（窗口可移动/滚动）。
- 燃料消耗滑块 min=0.01/max=1（f→x: `trackX + (f-0.01)/0.99*trackW`）；载重滑块按 0→max 线性映射。

## 读取结果

- 航段表格在表单下方（`# 类型 目的地 耗时 距离 损伤 费用 消耗`），跨星系含 起飞/离港/跃迁/进近/着陆 段。
- **系内（同星系）飞行的段结构是「转移」（TRANSIT）**（行星起飞/着陆另加「起飞」「着陆」段），
  **没有**「离港/进近」段；原生样本（保留，真实数据）：用户 SFC 原生计划
  ZV-307a → ZV-307/Antares Station（勾选「使用跃迁点」态）= **单段转移 101,655,808 km / 43分59秒 / 2655 单位 STL**。
  转移段距离是**转移路径的弧长、随计划时刻（相位）漂移**，不是航线常数（同航线同船同 f 也会变）。
- **系内航线的路程与是否勾选「使用跃迁点」无关**（结论保留，但判据换成代码事实）：`route-planner.planRoutes()`
  把起终点都解析成**星系 id**（`resolveSystemId`）后跑两次 Dijkstra；系内航线 `from === to` → Dijkstra 在
  `cur === to` 处立即 break（`route-planner.ts` 第 96–98 行），两种模式都是单元素路径 → `buildRoute` 的
  `for (i < path.length - 1)` 不执行（第 138 行，函数体 129–150 行）⇒ `legs = []`、`gatewayCount = 0`
  → `planRoutes` 只返回 `natural`，`gateway` 候选恒空（第 172–181 行；`gatewayCount > 0` 不成立）；`ftc-compute.ts` 第 395–396 行的
  `planned.gateway ?? planned.natural` 两种模式取到**同一个** route 对象。原生侧只有**勾选态**这一条样本，
  **不存在**直飞态原生样本（见下条）。
- **⚠️ 旧「两者差 0.05% / 两种模式路程相同」已作废（跨样本无效）**：`101.7053M km`（= 68.0562M + 33.6491M）
  从来不是原生值，是**已删除的自建轨道模型**的估算行（FTC 面板「航线分段（模型估算）」）；把原生
  101,655,808 km 与这个估算行相比，等于拿两个不同来源的数硬凑出「0.05%」。旧文案还把它硬编码进 SFC 提示
  模板，导致同一条警告里既打印本次读数（实机日志 88.87M）又说「差 0.05%」—— 两者实差 12.6%，自相矛盾。
  规则：**文案里的数字一律现算，禁止复用历史样本**，跨样本比较一律无效。详见 `docs/feature-patterns.md`
  「系内「转移」（TRANSIT）段：距离不是航线常数 + 提示/日志降噪」条目。
- ~~同星系走跃迁点路线显示 转移+着陆（转移距离 ~520M km）；关闭「使用跃迁点」才是直飞（~4,693 km）~~
  **已删除（2026-09-23，无数据支持）**：520M km 是下表 HRT → VH-331g 的**转移**段距离（量级 = 两体到恒星的
  轨道半径之和：HRT 46.81M + VH-331g 440.95M = 487.8M km），属系内飞行的常规结构，不是「跃迁点」造成的；
  而「~4,693 km」在任何采集数据里都不存在（同数据集里千米级的只有 起飞 4,552 / 着陆 4,779 km）。
  引用该行的旧注释/文案已同步更正（`system-bodies.ts`、`fuel-model.ts`、`route-planner.ts`）。
- 着陆/起飞距离可能因轨道运动漂移，跨数据点比较时注意。

## 数据记录建议

- 记录：蓝图配置（引擎/油箱/货舱/船板/整备质量/推力/G）、f/r、载重、各段耗时/距离/燃料。
- 采集后**恢复蓝图原始配置**（改回原引擎/货舱等）并保存，避免影响用户蓝图。
- 历史数据见 `data/ftc-calibration/btf-load-sweep-2026-08-29.md`；拟合脚本 `scripts/analyze-btf-load.py`。

## 转移段口径标定结论（2026-09-23 完成；原「待办实测」）

- **燃料口径 = 罐口径（已完成，2026-09-23）**：`F = 0.98 × 罐 × min(f, 0.5)`（= 两段 `0.49×罐×f`），
  **与距离无关、与载重无关、f ≥ 0.5 饱和**；BTF 28 点最大误差 **3.3%**。判据就是原先设计的
  「换罐实验」（只看燃料是否随罐变、不看距离）；`C_F×f×d` 口径**已证伪**：同航线罐 1500 高 **10.0×**。
- **时长口径也已标定（同批）**：`t = d / (V_SAT(引擎) × (min(f,0.5)/0.5)^k(引擎) × (整备质量/当前质量)^0.75 × 3600) / 状况`
  —— §2 标准引擎 12 点最大误差 **8.8%**、§1 质量曲线最大 **9.4%**、§3 交叉检验 ≤**7.8%**；原计划
  「顺带记录转移耗时」的目的（把时长从巡航式 `d/v(f)` 换成标定式）已完成。**残余局限**：未实测引擎
  （advanced/glass/hyperthrust）回退标准引擎参数；距离只在一个族上标定，跨距离靠用户原生样本交叉校验。
- **`transitCalibrationPending` 门已删除 ⇒ 系内航线已恢复写滑块**（拿到原生转移段记录即可算、可写）。
  自动化回归 `scripts/verify-ftc-gap-guidance.mjs` 的断言**已随口径更新**：⑥ 转移段口径已标定 →
  不报缺、按罐口径算燃料并写滑块；⑦ 无记录时给「生成一次计划」且**不得**出现「口径未标定」字样。
- **⚠️ 罐容量读数存疑（未修）**：FTC 面板读的是蓝图 `performance.stlFuelCapacity`；用户船样本 2655u
  需 **罐 8000 + f≈0.34** 才能解释（面板显示 3500）。罐是乘性因子，不影响选出的最优 f，但影响燃料总量
  显示与缺口判断 —— 见 `docs/feature-patterns.md` 「系内「转移」段几何 + 燃料口径标定 + 星系 id 反查」末项。
- 口径细节与完整数字见 `docs/feature-patterns.md` 的 FTC 条目（基准数据：
  `data/ftc-calibration/btf-load-sweep-2026-08-29.md`；拟合脚本 `scripts/analyze-btf-load.py`；
  对应实现：`fuel-model.ts` 的 `STL_TRANSIT_*` 标定块与 `computeFuelOption()` 的系内分支）。
